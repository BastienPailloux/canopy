# Canopy V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Une application Mac qui gère worktrees, sessions Claude Code, code, diff et terminal dans une seule fenêtre, assez solide pour remplacer l'IDE une journée entière.

**Architecture:** Process principal Electron = toute la logique (git, sessions SDK, terminaux, recherche, LSP) dans des modules testables sans Electron. Le renderer React ne fait qu'afficher, via une API IPC typée exposée par le preload. Sessions et terminaux sont globaux au process principal, donc ni changer de vue ni changer de repo ne les interrompt.

**Tech Stack:** Electron 45, electron-vite 6, electron-builder 26, React 19, TypeScript 7, zustand 5, `@anthropic-ai/claude-agent-sdk` 0.3.319, `@xterm/xterm` 6, node-pty 1.1, monaco-editor 0.57, `@vscode/ripgrep` 1.18, typescript-language-server 6, chokidar 6, vitest 5, `@playwright/test` 1.65.

**Spec:** `docs/superpowers/specs/2026-11-07-canopy-design.md`. Maquette : https://claude.ai/artifact/WcXTxNhxSWaDL28ttqjZye (écrans 1 « Sessions » et 2 « Code »).

**Périmètre :** étape 1 de la spec uniquement. Tickets, Linear et maquettes auront leur propre plan, après le résultat du spike.

## Global Constraints

- macOS uniquement, Apple Silicon. Node >= 18.14 requis par le SDK.
- Interface en français. Thème sombre : fond `#0D0E10`, panneaux `#131518`, bordures `#262A30`, texte `#E7E9EC`, secondaire `#A0A7B2`, accent `#A78BFA`, ajouts `#3FB950`, suppressions `#F85149`, attention `#E3B341`. Polices Inter et JetBrains Mono.
- `contextIsolation: true`, `nodeIntegration: false`. Le renderer n'accède au disque et aux process que par l'API `CanopyApi`.
- `git` et `gh` de la machine, jamais de réimplémentation. Tout appel passe par `execFile` avec tableau d'arguments, jamais par une chaîne shell.
- Aucun serveur, compte Canopy ou télémétrie.
- Une session ou un terminal ne s'arrête jamais à cause d'un changement de vue, d'onglet, de worktree ou de repo.
- Le diff compare le working tree, non commité inclus, au merge-base avec `origin/<défaut>` si le remote existe, sinon avec la branche locale par défaut.
- Secrets dans le trousseau macOS via `safeStorage`, jamais en clair.
- Logo retenu : piste A « Trois couronnes ». Fond `#1A1630`, SVG `viewBox="0 0 100 100"` : `<circle cx="31" cy="50" r="17" fill="#6D5BD0"/><circle cx="69" cy="50" r="17" fill="#7E6BE0"/><circle cx="50" cy="40" r="21" fill="#A78BFA"/><path d="M50 84V58M50 72C50 64 36 66 34 58M50 72C50 64 64 66 66 58" stroke="#F4F1FF" stroke-width="4.5" fill="none" stroke-linecap="round"/>`. Wordmark `canopy` en minuscules, Space Grotesk 600, `letter-spacing: -0.02em`.

## Review Focus

1. App lancée depuis le Finder : le `PATH` hérité ne contient ni `gh`, ni `node` via nvm. Canopy doit utiliser le `PATH` du shell de connexion de l'utilisateur (Task 3).
2. Repo sans remote, ou sans `origin/HEAD` : diff et commits d'avance fonctionnent sur la branche locale par défaut (Task 3).
3. Worktree en HEAD détaché, chemin avec espaces ou accents, branche avec `/` : listé et utilisable sans erreur (Task 3, Task 4).
4. Fichier binaire, très gros, renommé ou non suivi : le diff reste exact et l'éditeur ne gèle pas (Task 4, Task 9).
5. Worktree supprimé hors de Canopy pendant qu'une session ou un terminal y tourne : l'entrée disparaît avec un message, l'app ne plante pas (Task 7, Task 12).
