# Onglet PR (CAN-5) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A « PR » tab shows the pull request of the selected worktree's branch and does there everything GitHub's PR page does (read, comment, review, request reviewers, assign, label, checks, merge, auto-merge, revert), then cleans the branch and the worktree up after a merge started from Canopy.

**Architecture:** The main process talks to GitHub only through `gh` behind a `PrGateway` interface: `ghGateway` (real, built on an injectable `GhRunner`) and `fakeGateway` (in-memory, behind `CANOPY_FAKE_GH` for the e2e). Reads are one GraphQL query parsed by hand into the shared `PrDetail`; every write is one `PrAction` sent through a single validated IPC (`pr:act`). Post-merge git work (`cleanup.ts`) runs in main on real repos and hands back what the renderer must still ask (worktree removal). The renderer has a `prStore` (zustand) polling the selected worktree, a `PrScreen` split by sub-tab, and pure models (`mergeModel.ts`, `prPrompts.ts`).

**Tech Stack:** Electron, React 19, TypeScript strict, zustand, vitest, Playwright, `gh` ≥ 2.61 (installed: 2.61.0).

**Spec:** `docs/superpowers/specs/2026-11-09-pr-tab-design.md`. Layout and copy: artboard « 2b · Gestion de la PR (GitHub) » (`project/PullRequest.dc.html`) of `https://claude.ai/artifact/WcXTxNhxSWaDL28ttqjZye` (read it with the Artifact tool, `path: "project/PullRequest.dc.html"`).

## Global Constraints

- All GitHub access through `gh`, `execFile` with an argument array; user text (comments, bodies, commit messages) goes through stdin (`--body-file -`, `-F body=@-` or `--input -`), never interpolated into an argument that could start with `-` or into a shell.
- The GitHub token never reaches the renderer; main validates every IPC argument: absolute worktree path, PR number (positive integer), ids (GraphQL node id `/^[A-Za-z0-9_=-]{1,100}$/`, REST ids positive integers), logins `/^[A-Za-z0-9-]{1,39}(\[bot\])?$/` (teams `org/slug`), label names 1–50 chars, bodies ≤ 65 536 chars (GitHub's limit), paths relative without `..`.
- User-visible text in French with « », code and comments in English; style of the repo (2 spaces, single quotes, no semicolons).
- Fork PRs (`isCrossRepository`) are ignored, as today.
- Refresh: every 60 s while the tab shows; every 15 s while a check is pending or auto-merge is on; on entering the tab; right after each action. `PrCache` is cleared with `soon` after merge, close, reopen.
- Default merge method `squash` when the repo allows it; only methods the repo allows are offered.
- Claude's replies end with the exact line `— Claude via Canopy`; a comment whose body ends with it shows as « Claude · via Canopy ».
- Local branch deletion uses `git branch -D` only when the branch tip equals the merged PR's `headRefOid`; never `--force` anything else.
- Cleanup runs only for a merge started from the tab (auto-merge enabled from the tab included) with the box checked; a PR merged elsewhere changes nothing locally.
- The main checkout is never removed.
- Each « Claude » action starts a **new** session tab (never reuses the current one) and switches to Sessions.
- `CANOPY_FAKE_GH` is ignored when `app.isPackaged`.
- TDD for every task: failing test first. Before declaring done: `npm run typecheck && npm test && npm run test:e2e`.

## Review Focus

1. **A stale answer for another branch**: the user switches worktree or branch while a `prView` is in flight → the answer is dropped, the tab never shows the previous branch's PR (Task 6 test `drops a view answered for a branch no longer current`).
2. **gh fails mid-action** (network, logged out, 422 from GitHub): the error shows in French with GitHub's message, the displayed PR stays as it was, a failed poll never blanks the tab (Task 6 `a failed refresh keeps the last PR`, Task 3 `rejects with gh's stderr`).
3. **Merge succeeded, a cleanup step failed** (switch conflict, remote branch protected): the merge is reported done, the failing step is reported, no later destructive step runs (Task 5 `stops after a failed switch, keeps the local branch`).
4. **Big PRs**: more than 100 threads, files or commits → the first 100 show with « N de plus — ouvrir sur GitHub » (`PrDetail.truncated`), nothing crashes (Task 2 `marks truncated connections`).
5. **Text with quotes, backticks, newlines, a leading `-`**, in a comment, a commit subject or a label → sent intact through stdin, never as a flag (Task 3 `sends bodies through stdin`).

export interface CleanupRequest { number: number; branch: string; headOid: string }
export type CleanupStep = { step: 'remote' | 'switch' | 'local' | 'update'; ok: boolean; message?: string }
export type CleanupOutcome =
  | { kind: 'dirty'; files: number }                                   // nothing done locally
  | { kind: 'switched'; branch: string; steps: CleanupStep[] }
  | { kind: 'proposeRemoval'; steps: CleanupStep[] }                    // renderer opens RemoveWorktreeDialog
  | { kind: 'failed'; steps: CleanupStep[] }                            // a step failed, later ones skipped

  - `cleanupAfterMerge(cwd: string, req: CleanupRequest, deps: { gateway: PrGateway; store: AppStore; prStates: (repo: string) => Promise<Map<string, 'open'|'merged'|'closed'> | null>; trusted: boolean }): Promise<CleanupOutcome>` — order: dirty check (`dirtyCount`) → `deleteRemoteBranch` (failure recorded, not blocking) → `nextBranch` → `switchBranch` (failure → `failed`, stop) → local delete.
